# Безопасность приложения

Коротко: у этого приложения нет сервера, аккаунтов и чужих данных. Поэтому
большинство способов «взломать» к нему просто не применимы — не потому,
что защита хорошая, а потому, что ломать нечего.

## Чего здесь нет, и что из этого следует

| Обычная мишень | Есть у нас? | Что это значит |
|---|---|---|
| Сервер с базой данных | нет | Нечего взломать и нечего украсть массово |
| Аккаунты и пароли | нет | Нечего подобрать, нечего слить |
| Личные данные на стороне | нет | Дневник лежит только в браузере владельца |
| Приём платежей | нет | Нет денежного мотива атаковать |
| Загрузка файлов на сервер | нет | Нельзя залить чужой код |

Всё, что человек записывает, остаётся на его устройстве. Даже если кто-то
полностью подчинит себе хостинг, он не получит ни одного чужого дневника —
их там физически нет.

## Что приложение отправляет наружу

Ровно один запрос: штрихкод в открытую базу Open Food Facts, и только когда
кода нет в локальной базе. Уходит одно число со штрихкода. Ни веса, ни роста,
ни записей о еде наружу не отправляется никогда.

## Что сделано для защиты

**Политика безопасности контента (CSP).** Странице разрешено загружать
только свои файлы. Скрипты с чужих адресов и встроенные скрипты
блокируются браузером. Сетевые запросы разрешены ровно в один адрес —
Open Food Facts. Проверено: попытка загрузить скрипт со стороннего CDN и
обратиться к произвольному сайту блокируется.

**Приложение нельзя встроить в чужую страницу** (`frame-ancestors: none`),
поэтому его не получится накрыть невидимым слоем, чтобы человек нажимал
не туда, куда думает.

**Браузеру запрещено угадывать тип файла** (`nosniff`) — картинку не
подсунуть под видом скрипта.

**Из железа разрешена только камера**, и только самому приложению. Микрофон,
геолокация, платежи, USB запрещены на уровне заголовка.

**Адрес страницы не утекает** на сторонние сайты (`Referrer-Policy`).

**Импорт резервной копии** отклоняет файлы больше 50 МБ, не пытаясь их
разобрать, и проверяет структуру перед записью.

**Зависимости.** `npm audit` — ноль уязвимостей.

## Чего защитить нельзя, и это надо понимать

**Код приложения открыт по своей природе.** Всё, что выполняется в браузере,
можно прочитать и изменить у себя на устройстве. Это верно для любого сайта
и любого веб-приложения без исключений. Никакая обфускация этого не меняет —
она лишь замедляет чтение.

Практически это значит: скопировать вашу вёрстку и логику может любой.
Защита здесь не техническая, а юридическая — авторское право.

**Изменить приложение у себя человек может.** Например, подправить норму
калорий в своей копии. Вреда никому, кроме себя, он этим не нанесёт.

## Реальные риски и что с ними делать

Самая вероятная опасность — не «взлом приложения», а угон вашей учётной
записи там, где оно лежит.

1. **Взлом аккаунта хостинга.** Если получат доступ к вашему Netlify или
   Vercel, смогут подменить приложение на своё по вашей же ссылке.
   *Защита:* длинный уникальный пароль и обязательно двухфакторный вход.
   Это самое важное действие из всего списка.

2. **Взлом почты, к которой привязан хостинг.** Через восстановление пароля
   получают всё остальное. *Защита:* двухфакторный вход и на почте.

3. **Подделка под ваше приложение.** Кто угодно может выложить копию по
   похожему адресу и выдать за вашу. *Защита:* давайте людям только один
   адрес и упоминайте его везде, где рассказываете о приложении.

4. **Заражённая зависимость.** Один из пакетов, на которых собрано
   приложение, может быть скомпрометирован. *Защита:* файл `package-lock.json`
   фиксирует точные версии, а `npm audit` проверяет известные проблемы.
   Запускайте его перед каждой выкладкой.

## Что проверять перед каждой выкладкой

```bash
npm audit          # известные уязвимости в зависимостях
npm test           # все проверки приложения
npm run build      # сборка не должна ронять ошибок
```

После выкладки один раз откройте приложение и убедитесь, что в консоли
браузера нет сообщений о нарушении CSP.
