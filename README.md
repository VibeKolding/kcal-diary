# Дневник калорий

Личный дневник питания. Работает без интернета, без аккаунта и без сервера —
все данные лежат в браузере на устройстве и никуда не отправляются.

## Запуск

```bash
npm install
npm run dev          # разработка на http://localhost:5173
npm run build        # боевая сборка в dist/
npm run preview      # посмотреть боевую сборку (нужно для проверки офлайна)
npm test             # 129 тестов
```

Service worker работает только в боевой сборке — в dev он отключён намеренно,
чтобы кэш не мешал разработке.

### Решения, о которых стоит знать

**Запись дневника хранит снимок пищевой ценности, а не ссылку на продукт.**
Если поправить продукт задним числом, вся история пересчиталась бы молча,
и графики за прошлые месяцы стали бы враньём.

**Обновление справочника сохраняет счётчики использования.** Посев с новой
версией перезаписывает вшитые продукты, и если не перенести `usageCount` и
`lastUsedAt`, у пользователя молча обнулятся «недавнее» и «часто» — самый
быстрый способ добавить еду. Это закрыто тестом.

**Обложка блюда собирается из его же состава.** По названиям продуктов
определяются две-три главные составляющие, и рисунок складывается из них.
Поэтому картинка не может разойтись с рецептом, а новое блюдо получает
обложку само. Каталог целиком рисованный — так он выглядит единым по стилю. Подстановка
фотографий сохранена: положите снимок в `public/images/recipes/` и впишите
блюдо в словарь `PHOTOS`, он заменит рисунок. Подробности — в
`public/images/recipes/README.md`.

**Разделение упражнений по полу — в подборе и подходах, а не в самих
движениях.** Мышцы у мужчин и женщин одни и те же, и «женский жим» был бы
выдумкой. Поэтому большинство упражнений общие, а отличаются две вещи:
какие движения вообще попадают в список и сколько подходов с повторами
у них написано. Тест следит за главным следствием: у упражнения, адресованного
одному полу, в подходах для другого стоит прочерк, и если забыть сузить
`audience`, второй пол увидит карточку с «—». Глазами это ловится, только
если открыть все двенадцать списков подряд.

**Справочник упражнений лежит модулем, а каталог рецептов — отдельным JSON.**
Разница в происхождении данных: рецепты собирает скрипт из базы продуктов,
и их числа надо сверять тестом с источником, а упражнения — неизменяемый
текст без источника. Модуль даёт проверку типов на сборке вместо разбора
схемы в рантайме и всё равно не попадает в первый чанк: раздел ленивый.

**Шаги раздела «Зал» разведены по адресам, а не по состоянию одного экрана.**
`/gym`, `/gym/:group`, `/gym/:group/:sex` — тогда системная кнопка «назад»
на телефоне возвращает на шаг назад, а не выбрасывает из раздела целиком.

**Карточка выбора пола обязана выглядеть законченной без фотографии.**
Снимки добавляются отдельно от кода и могут не появиться вовсе, поэтому
промах по файлу молча переключает карточку на силуэт с подсвеченной группой
мышц. Тот же приём, что у обложек блюд. Обратная сторона: опечатка в имени
файла не даёт ошибки, и после добавления снимков нужно глазами проверить,
что подменились все двенадцать, а не одиннадцать.

**Рецепты переехали в экран добавления еды, а вкладку в таб-баре занял зал.**
Пятая вкладка там уже была раньше и была тесной: шесть элементов по 60 px
ровно заполняют экран шириной 360 px, без запаса. Каталог блюд при этом
оказался ближе к месту, где он нужен, — рядом с поиском и штрихкодом.
Открытое блюдо держит не сам каталог, а экран добавления: карточка рецепта —
тоже выдвижная панель, и без этого она открылась бы поверх первой.

**Вес живёт в профиле, а его график — в отчётах.** Ввод веса — это факт
о человеке, как рост и возраст, и от него пересчитывается норма, поэтому
он рядом с анкетой. График — обратная связь, и ей место среди остальной
аналитики. Раньше график был на обоих экранах сразу.

**Таблица `activity` осталась в схеме и в резервной копии,** хотя тренировок
в интерфейсе больше нет: без неё копии, снятые раньше, перестали бы читаться.
Импорт теперь терпит и полное отсутствие этого раздела.

**Свинины нет ни в каталоге, ни в справочнике продуктов.** Из базы убраны
свинина, бекон, обычная ветчина, сосиски, колбаса и шашлык; осталась только
куриная ветчина. Проверяется тестами с обеих сторон — и по рецептам,
и по справочнику.

**Идентификаторы продуктов считаются из названия, а не из порядка в списке.**
При нумерации по порядку удаление одной позиции сдвигало бы идентификаторы
всех последующих, и ссылки на еду в «недавнем» и в сохранённых рецептах
начали бы указывать на чужие продукты.

**Посев удаляет продукты, исчезнувшие из справочника.** Иначе убранное из
базы навсегда осталось бы у тех, кто уже поставил приложение. Записи дневника
при этом не страдают: они хранят снимок ценности, а не ссылку на продукт.

**В каталоге нет свинины.** Ни в составе, ни в названиях, ни в шагах —
это проверяется тестом, потому что новый рецепт легко добавить и не вспомнить
про ограничение. Ветчина допускается только куриная, и это указано прямо
в названии блюда, чтобы заголовок не вводил в заблуждение.

**Каталог рецептов не хранит выдуманные калории.** Состав ссылается на
продукты вшитой базы, а БЖУ считает `scripts/build-recipes.py`. Тест сверяет
цифры каждого рецепта с суммой его состава: поправить продукт в базе и забыть
пересобрать каталог — значит незаметно начать врать в цифрах.

**Рецепт делится на вес готового блюда, а не на сумму ингредиентов.**
Килограмм сырого мяса даёт около 700 г жареного, но калории никуда не деваются —
они становятся плотнее на каждые 100 г.

**Норма не опускается ниже базового обмена.** При слишком агрессивном темпе
приложение поднимает её до безопасного минимума и говорит об этом вслух.

**Требования зависят от цели.** На снижении белок поднят до 2 г/кг — он
защищает мышцы в дефиците; на поддержании и наборе он ниже, зато жиры
возвращаются к 1 г/кг. Темп набора ограничен 0,5 кг в неделю: быстрее мышцы
не растут, остальное отложится жиром.

**Числовые поля хранят строку, а не число.** Привязка прямо к числу ломает
ввод: стоит стереть значение, как `Number('')` превращает его в ноль, поле
показывает «0», и набрать своё значение уже нельзя.

**Все одноколоночные сетки используют `minmax(0, 1fr)`.** Колонка `auto`
позволяет самому широкому ребёнку задать ширину трека: одно длинное название
блюда растягивало весь экран вбок, а поле ввода в паре колонок уезжало за
край, где до него не дотянуться.

**Состояние покоя задаётся в CSS, анимация только подводит к нему.** Если
написать наоборот — `opacity: 0` в базе, а видимость через анимацию, — то в
момент, когда браузер не рисует кадры, на экране не окажется ничего. Поэтому
заставка и эмблема включают анимацию лишь после первого настоящего кадра.

**Единственный сетевой запрос во всём приложении** — поиск штрихкода в
Open Food Facts, и только когда кода нет в локальной базе. Найденный продукт
навсегда оседает на устройстве и в следующий раз открывается без сети.

**Авторство подставляется из `package.json`.** Поля `author` и `version`
пробрасываются в код через `define` в `vite.config.ts`, поэтому подпись
на заставке и версия в профиле не могут разойтись с манифестом пакета.

**Заставка идёт по шагам, и порядок шагов — её смысл.** Знак собирается
сам по себе (0–0,9 с), после него поднимается название (0,82–1,24), за ним
строка про устройство (0,98–1,4), последней подпись автора (1,18–1,6), и
только тогда по ней проходит свет (1,68–2,4). Раньше текст выезжал, пока
кольцо ещё дорисовывалось, и порядок не читался. Отсюда же минимальное
время заставки 2,4 с в `App.tsx`: это длительность самой сцены, а не запас,
и уйти раньше значит оборвать последний шаг.

**Текст заставки появляется и смещением, и проявлением.** Раньше здесь была
только подвижка на восемь пикселей: при остановке кадров текст оставался
виден. Шаги так не читались, поэтому теперь работает и прозрачность, а
безопасность даёт другое: класс `.enter` навешивается лишь после первого
настоящего кадра. Если браузер не рисует вовсе, анимаций нет и весь текст
виден сразу. Состояние покоя по-прежнему задано обычными свойствами.

**У объёмного листа нет прожилки, и это решение, а не недоделка.**
Сквозная прорезь в детали такого размера показывает то, что за ней, а за
ней — собственное свечение знака и бегущий свет. От фазы света щель читалась
то золотой щербиной, то белой чертой, будто лист подчеркнули карандашом.
Широкая прорезь превращает лист в рваную фигуру. Стабильного вида у неё не
выходит, поэтому лист цельный: прожилка осталась только на плоском SVG-знаке,
где она нарисована штрихом и от освещения не зависит.

**Плоская заглушка подогнана под объёмный знак, а не наоборот.** Пока
едет чанк со сценой (154 КБ в сжатом виде), на месте эмблемы стоит SVG-знак,
и он же остаётся навсегда там, где нет WebGL. Чтобы подмена читалась как
появление объёма, а не как смена знака, у заглушки лист залит и без прожилки
(`solid`), масштаб поднят через `EMBLEM_FALLBACK_RATIO` (кольцо SVG занимает
80 % своего поля, в сцене — 70 % холста, без поправки знак прыгал в полтора
раза), а разрыв кольца довёрнут в то же место. Обычный знак — в профиле и
на онбординге — не тронут: там он стоит сам по себе, сравнивать не с чем.

**Время анимации знака считается от его появления, а не от загрузки страницы.**
С абсолютным `performance.now()` фаза парения и положение источников света на
каждом запуске были свои: один и тот же кадр выглядел по-разному, и мелкие
детали ловили блик случайным образом.

**Финальный акцент — перевод фокуса, а не просто подсветка букв.** Одной
бегущей по подписи искры мало: рядом стоят знак и заголовок той же яркости,
и глазу не за что зацепиться. Поэтому на 1,62 с знак отступает (масштаб 0,94
и прозрачность 0,6), название и строка приглушаются до 0,45, а подпись
подаётся вперёд (масштаб 1,14), чуть разряжает буквы и получает тёплое пятно
под собой. Приём из монтажа: внимание забирает не самый яркий объект, а
единственный оставшийся ярким.

**Заставка заканчивается на подписи автора.** Знак и заголовки встают
первыми, затем по буквам «BY KOLDIN» один раз проходит светлый блик, а
волосяные линии по бокам раскрываются наружу и ставят подпись в рамку.
При уходе знак и заголовки улетают вверх, подпись задерживается и чуть
подаётся вперёд — последнее, что остаётся на экране, это она. Блик сделан
движением `background-position` по заливке, которой покрашены сами буквы:
прозрачность не трогается, правило заставки соблюдено. Класс `shine`
включается только на заставке, в выходных данных подпись обычная.

**`background` сокращённой записью сбрасывает `background-clip`.** Подпись
покрашена градиентом, обрезанным по буквам. Стоило добавить блик через
`background:`, как заливка начала красить прямоугольник, и вместо имени на
заставке появилась золотая плашка. В `Signature.module.css` только
`background-image`.

**Светлая тема — основная, и она же стоит при первом запуске.** Системная
`prefers-color-scheme` намеренно не спрашивается: у первого запуска должно
быть одно предсказуемое лицо, а переключатель стоит в профиле. Сохранённый
выбор, конечно, главнее.

**Тема ставится до первой отрисовки, иначе запуск мигает чужим цветом.**
Атрибут в `index.html` один на всех, поэтому `public/theme.js` читает
сохранённый выбор и ставит `data-theme` вместе с `theme-color` ещё до
разбора тела страницы. Отдельным файлом, а не встроенным скриптом: CSP
запрещает inline, и ослаблять её ради трёх строк неразумно. Значение по
умолчанию продублировано в `theme.tsx` — разойтись они не должны, иначе
первый кадр будет один, а второй другой. Цвета манифеста и статус-бар iOS
тоже переведены на светлые: `black-translucent` рисует часы белым, а на
светлом фоне белое не читается.

**На светлом фоне стекло работает наоборот.** На тёмном карточка светлее
основы и рамка белая; на светлом белая рамка на белой карточке не видна,
поэтому она сиреневая, а карточку отделяет цветная тень. Заливка при этом
низкая (0.30) намеренно: карточки занимают почти весь экран, и при
непрозрачном стекле тема читалась бы белой, а не голографической.

**Два уровня «Зала» говорят разными языками.** На экране выбора группы —
анатомическая карта: тёмная фигура на прозрачном фоне, подсвечена только
целевая мышца (`images/gym/art/<group>.webp`, одна на группу, без деления
по полу). На следующем экране — фотография человека в движении с той же
багровой подсветкой (`<group>-<sex>.webp`). Внутри карточки упражнения — третий язык, диптих из
двух фаз движения (`images/gym/ex/<id>-<пол>.webp`). Карта отвечает «какая
мышца», фотография — «как это выглядит», диптих — «что происходит между
началом и концом повтора»; поставить фото на оба первых экрана значило бы
сказать одно и то же дважды, а шесть снимков в мелкой сетке не читаются.
Прозрачный фон у карт обязателен: карточка стеклянная, прямоугольник с
собственным фоном её разрушает. Нет файла — рисуется прежний силуэт
`MuscleArt`, то есть добавлять можно по одной.

**Хранилище помечается постоянным, и только у установленного приложения.**
По умолчанию браузер считает данные сайта расходным материалом и вправе
вычистить их вместе с кэшем, когда на телефоне кончается место. Команда
`persist()` меняет пометку на «это данные человека». Просим её один раз при
запуске и только когда приложение открыто с домашнего экрана: там браузер
почти всегда соглашается, а во вкладке часть браузеров показала бы на этот
запрос разрешение — окно на пустом месте у человека, который ничего не
нажимал. Промах ничего не ломает, поэтому запуск вызова не ждёт.

**Перед восстановлением из файла откладывается точка возврата.**
Восстановление стирает всё и заливает файл, а файл легко перепутать —
прошлогодняя копия, копия с другого телефона. Отменить это было нельзя:
сегодняшний день исчезал молча и навсегда. Теперь перед заливкой
сохраняется снимок текущего состояния в том же формате, что и копия, то
есть без вшитых продуктов и потому небольшой. Снимок живёт неделю, дальше
предложение «вернуть как было» только сбивало бы с толку: человек давно
живёт с восстановленными данными. На пустом дневнике точка возврата не
заводится — первое восстановление на чистом телефоне это переезд, а не
ошибка.

**Напоминание о копии живёт на главной, а не только в профиле.** Кнопка в
профиле была и раньше, но чтобы до неё дойти, нужно вспомнить о её
существовании и уйти с экрана, где ты только что записал ужин. Строка
появляется там, где человек находится, делает копию одним нажатием и
исчезает сразу после него: постоянная плашка «сделайте копию» перестаёт
читаться на третий день.

**Переход из «Избранного» считает пол, а не берёт его из профиля.** Звезда
стоит на упражнении, а не на разделе: мужчина вправе отметить подъём таза,
женщина — подтягивания, и «Избранное» на главной раздела показывает всё
отмеченное. А вот живёт упражнение только в том списке, который оставил
`pickExercises`, и у адресного движения этот список ровно один. Пока переход
подставлял `profile.sex`, он приводил в список, где упражнения нет: `?open=`
ничего не находил, карточка не раскрывалась, и клик умирал молча — без
ошибки, без пустого экрана, вообще без признаков поломки. Поэтому пол
вычисляет `exerciseSex`: профиль спрашивают только у движений, которые
подходят обоим. Правило лежит в `domain`, а не в разметке, потому что
проверить его можно только чистой функцией — компоненты здесь тестировать
нечем.

**Снимки упражнений не попадают в установочный кэш.** Обложки групп —
двенадцать файлов — предкэшируются вместе с остальным шеллом. Снимков
упражнений шестьдесят девять, и они утроили бы вес установки ради картинок,
до которых большинство не дойдёт. Поэтому `globIgnores` исключает
`images/gym/ex/**`, а правило `CacheFirst` кладёт снимок в кэш в момент
первого открытия карточки: посмотрели один раз — дальше работает офлайн.
Файла может не быть, и это нормальное состояние: блок просто не
отрисовывается, как и обложка группы подменяется силуэтом.

**Кэш снимков фильтрует ответы по типу, иначе он ломает сам сценарий.**
Хостинг отдаёт `index.html` с кодом 200 на любой ненайденный путь — иначе
прямое открытие `/recipes` давало бы 404. Значит отсутствующий снимок
приходит успешным ответом, а `CacheFirst` по умолчанию кэширует любой
успешный ответ. Без фильтра заглушка осела бы в кэше под именем снимка, и
файл, добавленный позже, не появился бы полгода — то есть сломался бы
именно тот порядок работы, ради которого всё и сделано: картинки кладутся
отдельно от кода и по одной. Поэтому у правила стоит
`cacheableResponse` по `Content-Type: image/webp`. Предел записей — 80 при
69 файлах: на шестидесяти ранние снимки вытеснялись бы у того, кто раздел и
смотрит.

**Снимок упражнения — диптих, а не один кадр.** Две фазы движения лежат в
одном файле: слева положение, с которого начинается повтор, справа дальняя
точка амплитуды. Двумя отдельными файлами это выглядело бы хуже, чем
кажется, — одна генерация даёт одного человека, один свет и один ракурс, а
две дают двух разных людей в соседних панелях, и глаз ловит подмену
мгновенно. Панели разделены тёмной полосой шириной 18 точек из 1200: на
узком телефоне кадр занимает 272 точки CSS, и полоса тоньше этой в кадре
уже не читается.

**Снимков 69, а не 41.** Упражнений сорок одно, но двадцать восемь из них
показываются обоим полам, и каждому нужен свой кадр: на предыдущем экране
пол уже выбран, и снимок человека другого пола отменял бы выбор, который
только что сделали. Остальные тринадцать адресные и обходятся одним файлом.
Отсюда путь `<id>-<пол>.webp` и число в тесте — от него же зависит предел
кэша.

**Стрелку направления рисует приложение, а не генератор.** Внутри картинки
она была бы растровой и мылила бы на плотном экране, гуляла бы по форме от
кадра к кадру, а ошибку в направлении пришлось бы чинить перегенерацией.
SVG поверх снимка решает все три: одинаковая на всех кадрах, резкая на любой
плотности, правится одним символом в справочнике. Тень под линией — второй
путь тем же контуром с широкой тёмной обводкой, а не `filter: drop-shadow`:
фильтр над `backdrop-filter` здесь запрещён по той же причине, по которой
запрещён `brightness` на стекле.

**Стрелка появляется только после того, как снимок загрузился.** Иначе она
висит над серой заглушкой и показывает направление движения на пустом
месте. Состояние берётся не только из `onLoad`: снимок из кэша бывает готов
раньше, чем React успевает повесить обработчик, событие теряется, и стрелка
пропадает начиная со второго открытия карточки — на устройстве с прогретым
кэшем и больше нигде. Поэтому после монтирования состояние спрашивается у
самой картинки через `complete` и `naturalWidth`.

**Направление движения — поле справочника, а не таблица рядом с путём.** В
разделе есть правило: выводимое из идентификатора живёт функцией
(`groupPhoto`, `exercisePhoto`), невыводимый факт — полем упражнения
(инвентарь, фокус, отдых, шаги). Направление ниоткуда не выводится. Решает
кардинальность: фактов сорок один, а картинок шестьдесят девять, потому что
мужчина и женщина двигаются в одну сторону, — значит факт принадлежит
упражнению, а не кадру. Плюс обязательное поле даёт проверку на сборке:
`tsc` сам перечислит незаполненные объекты. Отдельная таблица завела бы
второй список идентификаторов, а два списка расходятся всегда.

**Направлений четыре, а не три.** У «поперёк» нет знака: в тяге каната руки
идут к лицу, а в жиме ногами платформа уходит от тела — общая стрелка
показала бы одно из двух наоборот. Поэтому `left` и `right` разведены, а в
промте зафиксировано, куда повёрнут человек. У движений, где две руки идут
в разные стороны — разведения и махи, — ракурс обязан быть строго боковым:
иначе у движения два видимых компонента и одна стрелка врёт по определению.

**Предел ширины снимка стоит на рамке, а не на картинке.** Шторка тянется
во всю ширину окна, и на мониторе кадр без предела занял бы почти весь
экран. Если ограничить `<img>`, SVG останется шириной с рамку и стрелка
промажет мимо шва ровно на половину разницы. По той же причине нельзя
трогать `object-position`: `cover` обрезает кадр симметрично, и шов остаётся
на середине, только пока позиция по умолчанию.

**Стакан воды наполняется, а не просто стоит рядом с цифрой.** Уровень
жидкости в значке — то же число, что и дуга вокруг чипа, но дугу нужно
сравнивать глазом, а налитый стакан понятен мгновенно. Рисуется вектором:
форма стакана служит обтравкой, поверхность с мениском, градиент от
`--water-1` к `--water-2`, блик по левой стенке. Фотореалистичный рендер
здесь не подходит и его не стоит возвращать: значок сорок точек, при таком
размере снимок превращается в кашу, требует своей версии под каждую тему и
выбивается из строя линейных иконок остальных категорий.

**Чип категории — тоже сосуд.** У записи дневника он наполняется на долю
дневной нормы калорий, которую занимает эта запись: видно, какая строка
съела день, а какая прошла незаметно. Одной заливки мало, она читается
пятном, поэтому у кромки стоит светлая черта — именно она превращает
заливку в уровень.

**Вода поднимается сдвигом, а не перерисовкой.** Жидкость нарисована на всю
высоту стакана и опускается через `transform`: перерисовывать путь каждый
кадр дороже и даёт рваное движение. Долив качает поверхность (`slosh`,
перезапуск через смену `key`), по поверхности медленно идёт блик — тот же
приём, что у кольца на заставке. Всё гасится при `prefers-reduced-motion`.

**Иконки собираются скриптом `scripts/build-icons.py`.** Для Android нужен
отдельный файл `maskable`: телефон обрезает иконку под форму своей темы —
круг, каплю или скруглённый квадрат, — и знак в нём уменьшен, чтобы кольцо
не срезалось. iOS манифест не читает вовсе и берёт иконку только из
`<link rel="apple-touch-icon">` в `index.html`.

**Токены цвета живут только в `src/styles/tokens.css`.** Контраст текста
проверен в обеих темах: 15:1 у основного, 7,5–8,5:1 у вторичного,
4,6:1 у мелких подписей, 5,0–6,7:1 у золотых подписей и единиц в обеих
темах — все проходят WCAG AA. Золото замерялось не по токену фона, а по
реальному пикселю под текстом: за стеклом лежит цветное пятно, и самое
светлое место карточки даёт контраст ниже расчётного.

**Отклик на касание — один на всё приложение.** Токены `--press`,
`--press-strong` и `--dur-press` в `tokens.css`, класс `.pressable` в
`base.css`. Карточки и строки списков получают класс в разметке, `Glass`
с `onClick` сам становится `<button>` — так отклик, фокус с клавиатуры и роль
для скринридера приходят вместе. Кнопки-примитивы используют те же токены.
Тактильный отклик (`src/ui/haptic.ts`) вызывается только там, где что-то
сохранилось: запись в дневник, вес, вода. На обычные нажатия телефон
вибрировать не должен.

**Панель уходит с той же анимацией, что и приходит.** `Sheet` держит
последнее содержимое, пока уезжает вниз, — родитель к этому моменту уже
обнулил данные. Для этого компоненты-панели берут `useLast()` и передают
`open={value !== null}` вместо размонтирования. Грабер рабочий: панель можно
утянуть пальцем, порог 80 px.

**Числа докручиваются, а не перескакивают.** `useCountUp` анимирует только
смену значения; при первом показе число стоит сразу, иначе при каждом
возврате на экран оно бегало бы от нуля. При `prefers-reduced-motion`
возвращает значение как есть.

**Списки появляются каскадом через `@starting-style`.** Класс `.rise-in`
и индекс `--i` в разметке. Состояние покоя задано обычными свойствами:
браузер без `@starting-style` просто показывает элемент сразу. Тот же
принцип, что у заставки и эмблемы.

**Зерно лежит НАД карточками.** `#root::before` с SVG-шумом, обычное
наложение при малой прозрачности (`--grain`). Под стеклом его размыло бы
вместе с фоном, а режимы смешивания на телефоне заставляют пересобирать
сцену на каждый кадр.

**Смена темы и экрана — через View Transitions.** `startViewTransition`
там, где есть; иначе переключение мгновенное, как раньше. Атрибут темы
ставится в layout-эффекте: иначе браузер снял бы «до» и «после» с одной
и той же темы.

**Два шрифта, две роли.** `--font-display` (Manrope) — заголовки экранов
и карточек, крупные числа: `.t-screen`, `.t-card`, `.t-display`.
`--font-text` (Golos Text) — весь остальной текст, включая подписи и
единицы. Golos рисовался под кириллицу: буквы уже, длинные строки вроде
«неделя 0/7 в норме · серия 1» умещаются и читаются спокойнее, чем в
геометричном Manrope. Два шрифта дают иерархию без увеличения размеров.
Цена — 96 КБ на кириллицу и латиницу, они лежат в предкэше и грузятся один раз.

**Единицы и капслок — золото, а не серый.** Токен `--text-unit`: «/ 150 г»
у полос БЖУ и все заглавные подписи под числами. Перекликается с кольцом
и главной кнопкой, но темнее их, поэтому не спорит с акцентом. Отдельный
`--text-unit-hi` — для подписи ВНУТРИ кольца: под ней самое светлое место
карточки, и приглушённый тон давал там 3,7:1. Правило: заглавная подпись,
которая раньше была `--text-faint`, теперь `--text-unit`; обычные строки
текста остались на `--text-dim`, иначе золото залило бы экран.

**Шапка экрана — по центру, с золотой чертой.** Роли `.t-head`, `.t-rule`
и `.t-lead` в `base.css`, модули подключают их через `composes`. Заголовок
слева читался как ещё одна строка текста, и вкладку было не опознать с
одного взгляда; черта даёт разделу ось и повторяет приём подписи автора на
заставке, поэтому нового языка не появляется. Подпись под заголовком
получила меру строки в 34 символа: без неё длинная фраза расползалась во
всю ширину и центрирование только мешало. На «Сегодня» шапка — сетка из
трёх колонок (стрелка, дата, стрелка): две кнопки с одной стороны
перекосили бы ось, а так середина остаётся посередине независимо от
длины даты.

**Типографика и высоты — токены, а не литералы.** Шкала `--fs-*` в
`tokens.css`, роли `.t-screen` / `.t-card` / `.t-caps` / `.t-display` в
`base.css`; модули подключают их через `composes … from global`. Высоты
интерактивных элементов — `--h-sm/md/lg/xl` (36/44/48/54): всё ниже 44 —
только чипы. Текстовое поле одно — `src/ui/TextField.tsx`, `NumberField`
лишь чистит ввод поверх него. Иконки — `src/ui/Icon.tsx`, один viewBox,
толщина 1.75; толще только «+» в таб-баре.

**Удаление без подтверждения, но с откатом.** `deleteEntry` стирает сразу,
тост предлагает «Отменить» пять секунд, `restoreEntry` возвращает запись
с тем же id. Тост один на приложение (`src/ui/Toast.tsx`): новое сообщение
заменяет старое, очередь из тостов — уже не «короткое сообщение».

**Обновление приложения объявляется тостом.** Воркер в режиме `prompt`,
регистрацию делает `useAppUpdate` через `virtual:pwa-register/react`,
`injectRegister: false` — иначе воркер регистрировался бы дважды. Без хука
`onNeedRefresh` никто не слушал, и новая версия приезжала только после
закрытия всех вкладок. Пока на экране заставка, терять нечего — новая
версия ставится сразу и страница перезагружается; тост показывается лишь
тогда, когда обновление пришло к уже открытому дневнику.

**Вес за период — по датам, а не по числу записей.** `weightsForRange`
вместо `weightHistory(days)`: раньше «неделя» показывала семь последних
взвешиваний, разбросанных хоть по полугоду.

**Прогноз веса — по прямой через точки, а не по крайним.** `weeklyTrend`
в `src/domain/weight.ts` — линейная регрессия по последним взвешиваниям;
один тяжёлый ужин иначе выглядел бы как набор килограмма за день. Если
тренд ведёт не к цели, прогноза нет: обещать нечего. На графике точки —
шум дня, сглаженная линия — то, на что смотреть.

**Напоминания честные.** Веб-приложение без сервера не будит себя само:
таймеры живут, пока дневник открыт или свёрнут, и об этом написано в
карточке. Напоминание молчит, если дело сделано — ужин записан, вода
выпита, вес есть. Настройки в `meta.reminders`.

**Ноль в составе быстрой записи значит «неизвестно», а не «ноль».**
Блок «Быстро, без продукта» существует ради случая, когда калории прикинуть
можно, а состав нет. Состав в нём необязательный: свёрнут за кнопкой
«+ Указать БЖУ», чтобы блок оставался быстрым. Если его не заполнили,
запись получает флаг `noMacros`, и отчёт исключает такой день из средних
БЖУ целиком — иначе день с быстрой записью уезжал бы в среднее с нулевыми
белками при полностью учтённых калориях, и цифра занижалась тем сильнее,
чем чаще этим блоком пользуются. Сколько дней пошло в расчёт и сколько
пропущено, написано прямо в карточке. Записи, сделанные до появления
флага, узнаёт `isMacroBlind`: у них нет ссылки на продукт при нулевом
составе, а у всего остального в дневнике ссылка есть. Калории можно не
вводить: они считаются из состава по 4/9/4, как в форме продукта ниже.

**Тренировка не увеличивает норму калорий.** Журнал подходов (`db.sets`)
— про прогресс в весах. Расход по формулам ошибается в разы, и
«заработанные» калории только сбивают дефицит. Таблица `activity` так и
осталась пустой ради старых копий.

**Схема базы — версия 2.** Добавлены `notes` (заметка к дню), `sets`
(подходы) и `favorites` (ключи `food:`, `recipe:`, `exercise:`). В копии
эти разделы необязательные: старые файлы читаются как раньше.

**Рецепт считается использованным так же, как продукт.** `addRecipeEntry`
поднимает `usageCount`/`lastUsedAt`, список рецептов сортируется по ним —
иначе свои блюда никогда не всплывали наверх.

**Эмблема заставки — настоящее 3D, а не картинка.** `src/app/emblem/`:
сцена на three.js (кольцо с разрывом из `TubeGeometry`, лист —
`ExtrudeGeometry` по пути SVG-знака, стекло через `MeshPhysicalMaterial`
с `transmission`). Библиотека лежит в отдельном чанке (~155 КБ gzip),
который грузится только на заставке; пока он едет или WebGL нет — плоский
SVG-знак на том же месте. Хореография: 0,9 с кольцо прорисовывается по дуге
и лист распускается, дальше знак парит, а два источника света ходят по
дуге — блик едет по стеклу. Наклон за пальцем и гироскопом делает `useTilt`
без React-состояния (iOS спрашивает разрешение только из жеста — на первом
касании). Заставка держится не меньше 1,8 с. Для проверки на телефоне и
снимков: `/?splash=1` держит заставку до касания, `&emblemT=0.4` замораживает
появление на нужной доле. Сравнивались ещё рендер с наклоном и три слоя
`webp` — они давали тот же вид только в покое, без бегущего света; убраны.

**Фон живой и рисуется на одном маленьком canvas.** `src/app/Backdrop.tsx`
рисует пятна на холсте в четверть экрана (один пиксель на четыре) 30 раз
в секунду, браузер растягивает его на весь экран — растяжение само даёт
мягкость, `filter: blur` не нужен. Под стеклом карточек лежит один слой
без фильтров и без анимации transform: слоистый вариант (пятна-`div` с
blur и keyframes) заставлял `backdrop-filter` пересобирать фон, и свечение
внутри карточек мерцало. Движение: дрейф по петле Лиссажу (11–16 с, у
каждого пятна свои), дыхание ±14 % (6–10 с), параллакс от прокрутки с
инерцией — ближние пятна едут быстрее дальних. Цвета только в `tokens.css`
(`--glow-1…6`, `--glow-saturate` применяется к ним заранее), геометрия — в
`Backdrop.tsx`. Заставка лежит на этом же фоне. При `prefers-reduced-motion`
и в свёрнутой вкладке рисуется один кадр.

**На стекле нет `filter` при наведении.** `filter: brightness` на элементе с
`backdrop-filter` создаёт новую поверхность отрисовки, и при наведении
курсора карточка дёргалась, а свечение под ней мигало. Отклик — только
нажатием (`--press`).

**Отклонение от нормы показано числом, а не переполнением полосы.** Пара
«208 / 82 г» требует считать в уме, поэтому рядом стоит капсула `+126`. Полоса
осталась прежней: она упирается в край, а смысл несёт капсула — нарисовать
кусок «сверх нормы» значило бы растягивать шкалу под самый плохой день и
менять масштаб всех остальных. Тон капсулы вторичен: знак `+` / `−` и слово
для скринридера есть всегда.

**Коридор ±10 % один на всё приложение.** `TOLERANCE` объявлена в
`domain/nutrition.ts`, её берут и `deviation()` для капсул, и `verdict()` с
`accuracy()` для оценки дня. Раньше десятая доля была записана литералом в
двух местах и могла разойтись. Внутри коридора капсула говорит «в норме», а не
`+6`: взвешивание еды всегда приблизительно.

**Подсказка столбца в отчётах — свой компонент.** Дефолтный `Tooltip` recharts
даёт одну строку, а вопрос у графика другой: не «сколько съел», а «насколько
мимо и за счёт чего». `DayTooltip` показывает калории с отклонением и три
нутриента со своими. В днях с быстрыми записями (`noMacros`) капсулы БЖУ не
показываются вовсе — состав там неполный, и отклонение считать не из чего;
вместо них приписка. Ширина ограничена 208 px, иначе длинная приписка
растягивает подсказку на всю карточку. Сам график помечен `aria-hidden`,
поэтому те же числа продублированы в списке `sr-only`.

**Итог периода считается по дням с записями, а не по всем дням.** Сравнивать
еду за четыре дня с недельной нормой бессмысленно, поэтому в сумму норм идут
только те дни, где дневник вёлся, а в шапке карточки стоит «за 4 дня из 7».
Баланс отвечает на вопрос, которого не видно в среднем: перебор одних дней
гасится недобором других, и неделя выходит в норму, хотя ни один день в
коридор не попал. Чтобы ровная неделя и качели не выглядели одинаково, под
итогом стоит разбивка «2 дня сверх нормы · 2 ниже · 2 в коридоре».

**БЖУ в итоге считаются по своему числу дней.** День с быстрой записью знает
калории, но не знает состав, поэтому идёт в баланс калорий и не идёт в БЖУ:
иначе сумма белка занижалась бы тем сильнее, чем чаще пользуешься быстрой
записью. Отсюда два счётчика в одной карточке (`macroDays`, `macroSkipped`) и
приписка внизу. Карточка «Средние БЖУ за период» растворилась в этой же:
средние за день остались одной строкой под суммами.

**Капсула отклонения — один компонент `ui/Delta.tsx`.** Её показывают полосы
БЖУ, подсказка графика и итог периода. Режим `word` говорит «в норме» внутри
коридора, `number` всегда печатает число — в подсказке важнее компактность.
Цвета живут глобальными ролями `.u-delta*` в `base.css`, у светлой темы для
перебора и попадания отдельные переопределения: те же смеси дают на светлом
3.1:1 и 4.4:1, ниже AA на 11 пикселях.

**Таб-бар — стеклянная трубка, а не плашка.** Раньше он заливался ровным
`--glass-strong` и на светлой теме читался молоком. Теперь у него тот же язык,
что у карточек: грань `::after` в две линии (яркая сверху слева, слабое
отражение снизу справа), свет от верхнего края и `saturate` как у `Glass` —
на 1.7 сильное размытие сводило фон под баром в серое. Свет лежит слоями
`background`, а не в `::before`: позиционированный псевдоэлемент рисуется
поверх вкладок и выбеливает иконки.

**Подложка под баром — только в тёмной теме.** На светлой контраст держит
тёмный текст, и бар остаётся по-настоящему прозрачным (7:1). На тёмной сквозь
него проходило яркое пятно фона, и подпись над ним падала до 3.3:1 — там
включается `--glass-scrim` в два слоя, как у карточек, и получается 5.2:1.
Это тот самый случай, ради которого подложка у `Glass` вообще появилась.

**Значок приёма пищи показывает время суток, а не еду** (кроме перекуса). Тарелка с рыбой при
тридцати пикселях превращается в пятно, а рассвет, полдень, серп и облако
различаются силуэтом — полукруг над чертой, круг с лучами, серп, яблоко —
и вдобавок цветом. Силуэта одного оказалось мало: два круглых значка в
одинаковом золоте всё равно читались как один, поэтому рассвет розово-коралловый
и без лучей, полдень золотой и лучистый, ночь фиолетовая. Перекус выпадает из
ряда намеренно: часа у него нет, он случается между приёмами, поэтому у него
предмет, а не время — зелёное яблоко. Это
единственное место, где картинка приёма живёт; `MealIcon` сначала пробует
готовый рендер из `public/images/meals/`, а если файла нет — рисует ту же
сцену вектором из токенов палитры. Отсутствие файла штатно, как у снимков
в «Зале».

**Рендеры чистятся перед установкой.** Генератор отдаёт картинку с прозрачным
фоном, но по краю оставляет полупрозрачную цветную бахрому, а у «ужина» —
белый ореол в половину кадра. Поэтому альфа режется по порогу 180, дырки
внутри заливаются, острова меньше сотой доли главного пятна выбрасываются, а
у «ужина» дополнительно снимаются ненасыщенные светлые пиксели — сам серп
фиолетовый, ореол белёсый. Дальше кадр обрезается по объекту, дополняется до
квадрата с полями в 10 % и уменьшается до 256 px. Четыре файла весят 47 КБ и
лежат в предкэше: исключать такую мелочь незачем.

**Движение значков — лёгкая петля без появлений.** Фигура смещается на полтора
пикселя и наклоняется на пару градусов, прозрачность не трогается вовсе:
мигание на четырёх карточках сразу читается как дефект. Задержки у приёмов
разные (`--i` с отрицательным знаком), иначе четыре значка качаются строем и
движение выглядит механическим.

**Шапка приёма выравнивается по центру, а не по базовой линии.** Слева теперь
группа «значок + слово»; на общей базовой линии её baseline берётся от чипа, и
«0 ккал» справа уезжало вниз.

**Снимок в карточке лежит выше внутреннего света стекла.** У `Glass` есть
`::before` — белая плёнка от верхнего края к середине, которая и делает
карточку стеклянной. Поверх фотографии она читалась туманом: верхняя половина
кадра выбеливалась. Теперь `.sexCover` получает `position: relative` и
`z-index: 1`, поэтому свет остаётся на тексте под снимком, а сам снимок чист.
Вместо тумана по кромке снимка идёт грань из тех же `--edge-*`, что у
карточек: стекло, а не дымка.

**Анатомия на обложках усилена обработкой, а не фильтром.** CSS-фильтр поверх
`backdrop-filter` в этом проекте запрещён, поэтому контраст поднят в самих
файлах: тёплые насыщенные пиксели (багрянец мышцы и золотой контур) ловятся
маской по HSV — оттенок в красном крыле круга и насыщенность от 95, — и
внутри маски идёт усиление цвета, контраста и мягкая резкость; снаружи кадр
чуть глушится. Маска размывается на 2.5 px, иначе граница усиления читается
ступенькой. Скрипт и оригиналы лежат в рабочей папке сессии.

**`npm run build` сначала проверяет баланс скобок в CSS.** Незакрытая скобка в
глобальном файле в dev незаметна (Vite подключает файлы по отдельности), но в
сборке всё склеивается в один файл, и одна скобка проглатывает стили всех
последующих компонентов.

## Как проверить офлайн

```bash
npm run build && npm run preview
```

Откройте приложение, дождитесь регистрации service worker (пара секунд),
затем остановите сервер и перезагрузите страницу. Приложение должно открыться
целиком: дневник, поиск по базе, отчёты.

## Резервные копии

Данные живут в IndexedDB этого браузера. Их сотрёт очистка данных сайта, и они
не переедут на другой телефон сами. Установленное на домашний экран
приложение просит систему пометить хранилище постоянным — тогда его не
вычистят при нехватке места; состояние видно на экране профиля. Профиль → «Скачать копию» сохраняет всё
одним JSON-файлом; «Восстановить из файла» возвращает его обратно. Если копии
нет больше недели, приложение напоминает об этом на экране профиля.

## Безопасность

У приложения нет сервера, аккаунтов и чужих данных, поэтому большинство
атак к нему неприменимы. Настроены CSP, запрет встраивания в чужую страницу,
`nosniff`, ограничение доступа к железу и потолок на размер импортируемой
копии. Разбор рисков и что проверять перед выкладкой — в [SECURITY.md](SECURITY.md).

## Как выложить людям

Приложение статическое и не требует сервера. Самый быстрый способ — собрать
и перетащить папку `dist` на [Netlify Drop](https://app.netlify.com/drop):
получится ссылка, по которой дневник ставится на домашний экран и на Android,
и на iPhone. Подробности и другие варианты — в [DEPLOY.md](DEPLOY.md).
